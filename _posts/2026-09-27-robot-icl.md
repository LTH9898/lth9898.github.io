## Why a policy needs contexts?

VLA policy can write as the function $\pi$

$$
\pi(a_t|o_t, l)
$$

- $o_t$ : current frame observation
- $l$ : language instruction
- $a_t$ : next action

The form is clean and it trains well. But it smuggles in a strong Markov assumption.

History of the past is not explicitly showing to the model. The history has been compressed into the weights implicitly.

Inside the training distribution, markov assumption is fine - Fixed ( camera, arm, table height, bounded task set ) setting, the model only has to learn one mapping from observation to action.

However, in real and OOD setting it goes different.

- the current frame doesn’t reveal how far into the task you already are;
- the camera moved, so the mapping between pixel motion and robot coordinates changed.
- the arm or the end-effector was swapped, so the same action command now means different kinematics;
- the same task admits many styles - fast, slow careful, brutal..
- new obejcts, new scenes combinations that never appeared in training.

**SO, we need contenxt **$\mathcal{C}$**. The current observation is not sufficient to determine the action, and the missing piece happens to be available somewhere else.**

$$
\pi (a_t|o_t,l,\mathcal{C)}
$$

$\mathcal{C}$ is the context. Trajectory, a human video, a goal image, a few seconds of the robot’s own poking around, o rthe execution of this epsiode.

---

## What should go in $\mathcal{C}?$

- In-context
  - acquisition happens inside the context window.
- Learning
  - the model ends up with a mapping it didn’t have before.
  - mapping holds on inputs never saw

#### Few shot prompting and its robot counterpart

![](/images/blog/robot-icl/01-image.png)

Robot sees the (observation, action) pairs from which the model figures out what this task is, then does it in a new scene.

Robot context’s content solve different uncertainties.

**(1) Which mapping to use.**

- Language instructions, goal images, URDF and other embodiment metadata.
- These say what the objective is - but the mapping that achieves it was already in the weights.
- The instruction just selects one

Ex) The model already learned function $f_1(x) =2x , f_2(x)=x^2$. If the context say choose #2, the model choose $f_2$. Context was useful but model didn’t learned something. The model only choose.

**(2) What the current state is.**

- The last several frames of execution.

Ex) The function $f$ is fixed. And lets say the past frames are context. Context is not solved, the solved context is not showed.

**(3) What the mapping itself is.**

- Demonstration trajectories, human video.
- The model didn’t know how to do this. → After reading the context, it does.

Ex) There is only (1→5), (2→7), (3→9) example pairs is given as context. Now model inversely infer the function.

**Only the third one is Learning**

- It resolves uncertainty about the mapping itself. The first two are just as useful and just as context-dependent, but after the model finishes reading, the function it uses to turn observations into actions has not changed.

$$
\pi(a_t | o_t,l,\mathcal{C}) = f_\theta(a_t|o_t,z), \quad z=z(\mathcal{C})
$$

- $f_\theta$ : This is trained model that have (weight $\theta)$
- $\bold z(c)$ : Compact or embedding of context $C$
